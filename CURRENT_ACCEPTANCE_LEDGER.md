## October 13 live session metadata checkpoint

- Added bounded background session state to the authenticated WebSocket channel. Success and validated failures carry commandId; unsolicited updates have type events and no commandId. Existing command/snapshot/event decoders and service authority are reused. The new envelope is documented in `docs/session-channel.md`; mobile transport remains unconnected.
- Outbox publication now takes the account lock, rechecks lease/revision/access/deadline, and atomically commits an empty PostgreSQL NOTIFY with completion. Superseded entries are distinct. This completion means a database wakeup was published, not client receipt or playback. Notifications never contain identifiers/private content; every subscriber fetches verified owned state.
- Dedicated API listeners reconnect after connection loss. Bound sockets use coalesced serial reads with a one-second fallback; this is recovery polling, not a chosen presence/paid-time policy. Every read verifies identity/controller/ownership; obsolete replay becomes a full snapshot rather than old playable work. Queued output is limited to64KiB; shutdown stops timers/sockets, drains work and releases listener connections.
